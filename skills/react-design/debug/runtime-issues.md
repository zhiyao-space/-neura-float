# Web / H5 运行时故障专题

只读取当前症状对应内容，不依次检查所有项目。结合实际调用代码判断根因；test/mock/fixture 等名称只是线索，不能覆盖状态码和运行证据。

## 重复请求与重定向

检查触发源 -> 状态写回 -> 重渲染/跳转 -> 再次触发的链路，包括不稳定的 effect 依赖、路由守卫、重复订阅、未清理的定时器和多层重试。确认根因后切断重复触发，不只加 try/catch、loading 或延时。权限尚未判定时保持不确定态；不得把限流当成未登录并反复跳转。复验同一路径，确认请求/错误不再持续增长。

## HTTP 429

顺序是代码缺陷 -> 不改变业务语义的并发优化 -> 确无优化空间时说明额度限制。先查循环、N+1、重复订阅、全量并发与重试放大，再考虑请求合并或懒加载。不得删业务数据、修改权限/查询语义、返回假数据或长期过期数据来压请求；不编造套餐权益。只有错误消失且业务语义不变才能宣称修复。

## HTML fallback、404、鉴权与服务端错误

API 返回 text/html 时先核对调用路径、代理、路由、部署结果和 SPA fallback，不先修改 JSON.parse/response.json。404 按实际路径与服务是否存在调查；401/403 区分用户输入/权限的预期拒绝与代码故障；5xx 依据服务端响应调查，不只改前端展示。云命令及接口实测遵循已有云技能，不在本文复制。

## CORS

依据目标归属、响应头、OPTIONS、credentials 判断真实 CORS。可控后端优先修服务端 headers/OPTIONS；确认第三方 API 不可控时才考虑受限服务端代理，云能力按现有云技能执行。

- 图片、字体、音视频、stylesheet、manifest 等低价值静态资源，不为消除提示默认生成代理；只有业务确需内容读取/导出时再评估。
- script/module 先查 URL、crossorigin、CDN 和打包，不用 API 代理脚本内容。
- EventSource/SSE、上传、大文件或依赖浏览器 Cookie 的请求先评估超时、流式转发和身份条件，不能直接套 JSON 代理。
- 代理须固定目标域名、路径、HTTP 方法与可转发头，不能做开放代理；密钥只留服务端。
- 平台云链路继续遵守托管 Client 和实例运行态保护，不切 URL、不另造 wrapper、不叠代理。
